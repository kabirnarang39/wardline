Wardline
GitHub Docs

Identity, policy, budget, and audit for every AI agent call

Wardline sits between your AI agents and everything they call — MCP servers, LLM providers, other agents — and enforces who's allowed to do what, how much, and logs every decision.

Get started → View on GitHub → 
go build -o wardline ./cmd/wardline
./wardline validate-policy --file policy.yaml.example
./wardline validate-config --config wardline.yaml.example
./wardline serve --config wardline.yaml.example

# in another terminal
curl -X POST http://localhost:8080 \
  -H "X-Wardline-Identity: agent-abc123" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"read_file"}}'
# -> allowed, forwarded upstream, and written to the audit log
01

Without a control plane, every agent call is a trust decision you're not making

Without Wardline

Any agent with network access to your MCP server can call any tool, with no per-identity limit, no audit trail, and no record of what happened after the fact.

With Wardline

Every call carries an identity, is matched against an explicit allow/deny policy, optionally counted against a budget, and written to a structured audit log — before it ever reaches your upstream server.

02

How it works

# policy.yaml
rules:
  - identity: agent-abc123
    tool: read_file
    effect: allow
default: deny
